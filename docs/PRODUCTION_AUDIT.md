# PennyGrade Production Audit

Audit date: 2026-11-04
Scope: repository review, local builds and route checks, desktop/tablet/mobile browser rendering, repeated read-only production HTTP checks, and a read-only Supabase migration-list attempt. Production payment, database, email, admin-write, and deployment operations were not performed.

## Summary

**Overall: FAIL.** Production remains on a release where six required routes return 404. Local builds and route checks pass, but Netlify Dev still fails to invoke the generated function and deployment access is unavailable. No real payments, refunds, customer orders, emails, or destructive database operations were performed.

## Architecture and implementation reviewed

- TanStack Start file-based routing, Vite, and Nitro's Netlify preset.
- Netlify publishes `dist`; tracked `public/_redirects` contains a catch-all rewrite to `/.netlify/functions/server`, and the generated function manifest also declares a `/*` route. The local Netlify CLI did not invoke that function even when the generated redirect file was removed for diagnosis.
- Netlify CLI validation found a duplicate `/assets/*` cache header because both Nitro's generated `_headers` and `netlify.toml` set it. The redundant TOML rule was removed; Nitro continues to generate the immutable asset cache rule.
- Supabase migrations, role checks, `create_verification`, and payment fulfillment routines.
- Server functions for public catalog, admin operations, orders, and tracking.
- Razorpay order creation, HMAC verification, payment lookup, and webhook handler.
- Resend transactional email outbox and order notification paths.
- Existing test suite and project environment-variable names. Secret values were not printed or added to documentation.

## Required next steps

1. Commit/review the current source changes using the team's normal release process.
2. Authenticate the Netlify CLI to the correct team/site, then create a preview from that exact commit and run `pnpm smoke:routes` against it. Do not deploy to production yet.
3. Identify the prior `/how-it-works` 500 in Netlify logs using its request ID; do not infer a root cause from successful retries.
4. Obtain Supabase project-admin assistance to verify migrations, schema, grants, and RLS.
5. Run isolated provider and database integration tests, including failed/duplicate payments and webhook retries.
6. Promote only after preview, integration, and security checks pass; repeat the smoke test on `https://pennygrade.in`.
